## 1. 문제 정의

### Who / What / When / Why

- **Who:** 화장품의 영문 성분표와 성분 기능을 해석하기 어려운 사용자
- **What:** 성분표 사진에서 성분명을 읽고, 성분의 6개 기능과 기능 기반 피부 타입 추천 이유를 제공한다.
- **When:** 사용 중이거나 구매를 고려하는 화장품을 살펴볼 때
- **Why:** 긴 성분 목록을 개별 검색하는 부담을 줄이고 기능 단위로 이해하도록 돕는다.

### 차별점과 범위

성분명을 나열하는 대신 보습·유연화 등 기능을 먼저 보여주고, 추천 이유와 실제 성분 목록을 단계적으로 펼쳐 볼 수 있게 했다. OCR로 읽은 이름은 등록명과 대조하며 조회되지 않는 항목은 분석에서 제외하고 별도 토글로 제공한다. 기존 모든 서비스에 없는 기능이라고 주장하지 않으며, 이 프로젝트의 구현상 특징으로 제시한다.

기능 분류는 직접 학습한 모델이고, 피부 타입 추천은 개발자가 작성한 규칙이다. 개인 피부 적합도나 임상적 효능, 성분 함량을 예측하는 서비스는 아니다.

### 정량 평가 기준

주 지표는 테스트 Micro F1, 보조 지표는 Macro F1·Micro Precision·Micro Recall이다. 초기에 수치 목표를 명시적으로 기록하지 못했다. **사후 정리한 비교 목표**는 성분명 입력 LR의 테스트 Micro F1(0.4441)을 개선하는 것으로 정의한다. 최종 배포 모델은 0.4567로 약 0.0126 높았지만, 이 목표를 실험 전 설정했다고 주장하지 않는다.

## 2. 데이터

### 출처·규모·구성

- 데이터: `COSING_Ingredients-Fragrance%20Inventory_v2.csv`
- 원천: 유럽연합 집행위원회 CosIng 성분 정보
- 공개 CSV 참고 페이지: https://huggingface.co/datasets/nad949/CosIng
- 공식 정보: https://single-market-economy.ec.europa.eu/sectors/cosmetics/cosmetic-ingredient-database_en
- 원본 크기: **30,080행 × 10열**
- 이름·기능 정리 후: 29,308행 → 중복 이름 통합 후 **29,307개 성분**
- 주요 입력: `INCI name`, `Chem/IUPAC Name / Description`
- 정답: `Function`을 분리한 다중 라벨
- **라이선스:** 사용한 CSV의 명시적 라이선스 및 재배포 조건은 아직 확인하지 못했다. 공개 열람 가능하다는 사실만으로 자유로운 재배포를 가정하지 않으며, 원본 CSV의 공개 배포는 보류한다. 제출 전 데이터 출처와 이용 조건을 추가 확인해야 한다.

성분명·설명·등록 기능을 함께 제공하므로 지도학습용 입력과 정답을 구성할 수 있어 선정했다. 피부 타입별 임상 적합도 정답이 있는 데이터는 아니다.

## 3. 데이터 전처리

| 처리 | 전 | 후 / 목적 |
|---|---|---|
| 문자열 공백 정리 | 앞뒤 공백, 빈 문자열 혼재 | strip 후 빈 문자열을 결측치로 통일 |
| 필수 열 결측 처리 | 성분명·기능이 없을 수 있음 | 입력·정답이 없는 행 제거 |
| 성분명 정규화 | 대소문자·문자 표기 차이 | NFKC, 대문자, 공백 정리 |
| 라벨 분리 | 쉼표로 연결된 Function 문자열 | 기능 목록으로 분리하고 빈 라벨·NOT REPORTED 제외 |
| 중복 성분 통합 | 같은 정규화 이름이 반복됨 | 기능 합집합으로 통합, 29,308 → 29,307행 |
| 설명 통합 | 같은 성분의 설명 중복·결측 | 중복 설명 제거 후 연결, 없는 설명은 빈 문자열 |
| 정답 인코딩 | 성분별 기능 목록 | MultiLabelBinarizer로 6열 0·1 정답 구성 |
| TF-IDF | 성분명 또는 성분명+설명 문자열 | 단어 1~2그램 + 문자 3~5그램, 최대 80,000차원 |

- 성분명 단위 무작위 분할: **70% / 15% / 15%, seed=42**
- 학습 **20,514**, 검증 **4,396**, 테스트 **4,397**
- 동일 정규화 이름을 통합한 다음 분할하여 동일 이름의 중복 유입을 방지했다.
- TF-IDF는 학습셋에서만 fit하고 검증·테스트에는 transform을 적용했다.
- 화학 계열이나 유사 설명까지 분리한 그룹 분할은 아니므로 새로운 계열에 대한 일반화를 보장하지 않는다.

## 4. 모델

| 구분 | 모델 | 학습 방식 | 선정 이유 |
|---|---|---|---|
| 베이스라인 | TF-IDF + One-vs-Rest Logistic Regression | 사전 학습 가중치 없이 직접 학습 | 빠르고 해석이 쉬운 선형 다중 라벨 기준 모델 |
| 비교·제안 | TF-IDF + One-vs-Rest Linear SVM | 사전 학습 가중치 없이 직접 학습 | 희소한 고차원 텍스트 특징에 대한 선형 분류 대안 |
| 추가 비교 | 고정 MiniLM 임베딩 + LR / SVM | MiniLM은 고정, 분류기만 직접 학습 | 문장 표현 변경의 효과 확인; MiniLM 파인튜닝은 아님 |

scikit-learn 구현으로 직접 학습했다. 알고리즘을 라이브러리 없이 처음부터 구현했다는 의미는 아니다. 각 기능을 독립적인 이진 분류 문제로 학습하여 여러 기능을 동시에 예측한다.

실험 순서는 성분명 입력 → balanced 보정 → 설명 추가 → MiniLM 비교 → 기능별 기준값 → SVM C 탐색이다. 최종 배포 설정은 **성분명+설명 TF-IDF / SVM C=0.1 / 결정 기준값 -0.5**이다. SVM 결정 점수는 확률이나 적합도 퍼센트가 아니다.

### 최종 모델 선택 근거와 한계

검증 Micro F1을 선택 기준으로 사용했다. C=0.1의 검증 Micro F1은 0.4493으로 C=1의 0.4461보다 소폭 높았고 학습·검증 격차도 작았다. 이 기준으로 배포 설정을 고정했다. 그러나 테스트에서는 C=1이 Micro F1과 Macro F1 모두 높았다. 따라서 최종 배포 모델이 모든 지표에서 최고라고 주장하지 않는다.

실험 중 테스트셋을 여러 번 확인한 한계가 있다. 이후 탐색이 테스트 결과의 영향을 전혀 받지 않았다고 단정할 수 없으며, 새로운 홀드아웃 데이터로 최종 평가해야 한다.

### 분석 2: 오류 사례와 희귀 기능

GLYCERIN은 초기 성분명 LR에서 피부 유연화를 양성으로 예측했지만 원본에 해당 세부 라벨이 기록되지 않았고, 등록된 피부 보호는 놓쳤다. 최종 SVM에서는 선택한 6개 기능 모두 음성으로 예측했다. 일반적인 보습 개념과 `HUMECTANT` / `SKIN CONDITIONING - HUMECTANT`의 세부 라벨 구분도 해석에 영향을 준다.

최종 배포 모델의 테스트 기능별 F1은 피부 유연화 0.5308, 피부 보호 0.3977, 피지 조절 0.0690이며 나머지 세 기능은 0이었다. Macro F1이 낮아 6개 기능을 고르게 안정적으로 예측하지 못했다. 수분 증발 억제의 테스트 양성은 2개로 평가 사례도 부족하다.

## 6. 서비스 프로토타입

### 사용자 흐름과 모델 연동

1. 휴대폰 카메라로 영문 성분표 촬영 또는 사진 선택
2. 브라우저의 Tesseract.js로 OCR 실행
3. 서버에서 성분명 정규화 및 등록명 대조; 조회 불가 항목 제외
4. 사용자가 성분명 목록 확인·수정 후 분석 실행
5. Python API가 저장된 joblib의 설명 사전·TF-IDF·SVM을 사용해 추론
6. 기능별 양성 예측 수와 규칙 기반 피부 타입 순위를 표시
7. 추천 이유·관련 성분·제외 항목·개별 예측은 토글로 확인

외부 생성형 AI API로 예측을 대체하지 않는다. OCR은 기존 라이브러리이고 기능 분류가 본인이 학습한 모델이다.

### 추천 규칙

| 피부 타입 | 연결 기능 |
|---|---|
| 건성 | 피부 보습, 피부 유연화, 수분 증발 억제 |
| 지성 | 피부 보습, 피지 조절 |
| 복합성 | 피부 보습, 피부 유연화, 피지 조절 |
| 중성 | 피부 보습, 피부 유연화 |
| 민감성 | 피부 보습, 불편감 완화 |

각 타입에 연결되는 양성 예측 성분의 고유 개수를 세며 동점은 공동 순위로 표시한다. 피부 보호는 특정 타입 점수가 아닌 공통 정보로 표시한다. 기능 범위가 넓은 타입이 유리할 수 있으며 성분의 농도·제형·개인 반응은 반영하지 못한다.

관리 방향 참고: [대한피부과학회 보습제](https://derma.or.kr/new/general/treatment.php?mod=document&uid=3326), [AAD 지성 피부](https://www.aad.org/public/everyday-care/skin-care-basics/dry/oily-skin), [Cleveland Clinic 피부 타입](https://health.clevelandclinic.org/understanding-skin-types), [2023 전문가 합의 논문](https://doi.org/10.1111/jocd.15519). 기능 연결과 순위 산식은 개발자의 구현이며 위 자료가 해당 산식을 검증한 것은 아니다.

### 사용 안내 및 예외 처리

영문 INCI 성분표를 정면에서 선명하게 촬영한다. OCR 오류는 분석 전 직접 수정할 수 있다. 한글을 영문 INCI로 자동 번역하지 않는다. 사진 해석 실패·조회 불가·양성 예측 없음은 서로 다른 상태로 안내한다. 첫 OCR 실행은 언어 파일 다운로드로 지연될 수 있다.

**제출 전 보완:** 촬영/성분 확인 화면, 추천 요약 화면, 추천 이유 상세 화면의 캡처 3장을 `assets/`에 저장하고 이 위치에 삽입한다. 캡처가 아직 포함되지 않았으므로 완료된 항목으로 간주하지 않는다.
실제 서비스 화면 녹화에서 추출한 캡처이다. 첫 화면은 사진 선택과 OCR 처리가 끝난 상태이며 촬영 순간을 보여주는 것은 아니다.

## 8. 실행 방법

### 학습

Google Colab에서 `notebooks/cosmetic_function_models_submission.ipynb`를 열고 CSV를 업로드한 다음 순서대로 실행한다. MiniLM 실험은 sentence-transformers와 PyTorch를 사용하고 CPU에서 오래 걸릴 수 있다. 노트북에 설치 셀이 포함되어 있다.

노트북은 반복 코드를 공통 함수로 정리하고 기존 출력을 보존했다. **정리 후 전체 재실행은 하지 않았으며 문법 검사만 완료했다.** 부록의 배포 파일 생성 코드는 초기 버전이므로 현재 서비스 파일을 덮어쓰지 않도록 구분한다.

## 9. Lessons Learned

### Plus

1. LR과 SVM을 같은 분할과 지표로 비교하여, 전체 성능과 희귀 기능 성능이 다르게 움직임을 확인했다.
2. 성분명에 설명을 추가한 실험으로 입력 정보의 중요성을 확인했고, 학습 모델을 실제 공개 웹서비스에 연결했다.

### Minus

1. 수분 증발 억제 등 희귀 기능의 데이터가 적어 개별 기능의 평가와 예측이 불안정했다.
2. 테스트셋을 실험 중 여러 번 확인했고 초기 정량 목표·라이선스·정확한 Python 버전 기록이 부족했다. 재현성과 평가 설계부터 정리할 필요가 있었다.

### Interesting

1. MiniLM을 고정 특징 추출기로 사용했지만 네 분류기 설정 모두 TF-IDF보다 검증 성능이 낮았다. 사전 학습 모델이 이 도메인에서 자동으로 유리하지는 않았다.
2. C=100에서는 학습 Micro F1이 0.9995에 도달했지만 검증은 0.3909로 낮아졌다. 높은 학습 점수가 좋은 서비스 모델을 의미하지 않았다.

### 문제 해결 사례: 낮은 재현율과 입력 정보 개선

- **문제:** 기본 LR에서 희귀 기능을 거의 예측하지 못했다.
- **원인 가설:** 높은 공통 기준값, 클래스 불균형, 성분명만 사용하는 입력 정보의 한계.
- **시도:** 기준값 탐색 → balanced 적용 → 성분 설명 추가 → MiniLM 비교 → 기능별 기준값 및 C 탐색.
- **결과:** 설명 추가 SVM C=1의 테스트 Micro F1은 0.4698로 성분명 SVM의 0.4253보다 높았다. 그러나 모든 기능을 고르게 예측하지 못했고 배포 C=0.1의 Macro F1도 낮았다. 노트북에는 단계별 문제·해결·한계를 기록했다.

### 문제 해결 사례: OCR 잡음과 복잡한 결과 화면

- **문제:** OCR 결과에 줄바꿈·기호·오인식이 섞였고 개별 성분 결과가 길게 나열됐다.
- **시도:** 정규화한 이름과 등록명을 대조하고 조회 불가 항목을 제외했다. 결과는 기능 중심으로 바꾸고 상세 내용은 토글에 넣었다.
- **결과와 한계:** 시연 제품의 37개 성분을 분석하고 9개 항목을 제외하는 흐름을 확인했다. 자동 제외된 성분에 중요한 정보가 있을 수 있으므로 전체 성분을 완전히 분석했다고 표현하지 않는다.
